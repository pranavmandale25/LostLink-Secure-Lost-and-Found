# Build LostLink — AI-Powered Secure Lost & Found Platform

You are a senior full-stack engineer, UI/UX designer, and AI product engineer.

Build a complete, polished, functional MVP called **LostLink**.

## 1. PRODUCT VISION

LostLink is an AI-powered lost-and-found platform designed primarily for **college campuses and communities**.

The problem is not simply that people lose things. The bigger problems are:

1. Lost and found information is fragmented.
2. It is difficult to match a lost item with a found item.
3. Anyone can falsely claim a found item.
4. Sensitive ownership information should not be publicly exposed.
5. Phones and laptops require additional security considerations.

LostLink solves this through:

**FIND → MATCH → VERIFY → RETURN**

The key differentiator is:

> **LostLink does not simply match a person with an item. It verifies ownership before enabling a safe handover.**

---

# 2. CORE USER FLOW

Implement this complete flow:

User A:

1. Creates a "Lost Item" report.
2. Uploads an image.
3. Adds public information.
4. Adds private ownership clues.
5. Submits the report.

User B:

1. Creates a "Found Item" report.
2. Uploads an image.
3. Adds basic information.
4. LostLink searches for potential matches.

AI Matching Engine:

1. Compares item descriptions.
2. Compares relevant visual information when possible.
3. Compares category, brand, color, location and approximate time.
4. Produces potential matches.
5. Never treats AI similarity as proof of ownership.

Ownership Verification:

1. Owner receives a potential match.
2. Owner can request verification.
3. System uses private ownership clues that were NOT publicly displayed.
4. Examples:

   * unique scratch
   * sticker
   * case design
   * hidden marking
   * contents
   * accessory
   * previous photograph
5. Claimant must provide matching evidence.
6. Failed verification should not automatically label the person a criminal or "fraudster."
7. Show "Ownership verification failed" or "Additional verification required."

Safe Handover:

1. Once ownership verification passes, enable a secure contact/handover flow.
2. Do not reveal unnecessary private information.
3. Both parties confirm the handover.
4. Mark item as RESOLVED.

## IMPORTANT SECURITY RULE

Never expose IMEI, serial numbers, private ownership clues, passwords, device unlock codes, or other sensitive information publicly.

Do NOT ask a finder to unlock a found phone or laptop.

Do NOT implement device-lock bypassing, password recovery, hacking, or unauthorized tracking.

The application should explicitly tell finders:

> "Do not attempt to unlock, access, or bypass security on a found device."

For device recovery, provide a general security checklist and optionally links/instructions for the user's existing official device-finding service.

LostLink itself should focus on **lost-and-found coordination and ownership verification**, not unauthorized device tracking.

# 4. ANTI-FRAUD / OWNERSHIP VERIFICATION

This is one of the most important features.

Do NOT reveal all item details publicly.

Example:

Public:

"Black Lenovo laptop lost near library."

Private:

* small red Arduino sticker
* scratch near left corner
* blue mouse
* specific previous photo

A fake claimant should NOT be able to simply read these details and repeat them.

The verification UI should work like:

---

## OWNERSHIP VERIFICATION

Potential match found.

To protect the owner, some identifying information is hidden.

Verification challenge:

"What unique mark is present on your device?"

[ Enter answer ]

[Submit Verification]

---

If successful:

✓ Ownership evidence matched
✓ Previous photo matched
✓ Identity verified

Ownership verification passed.

If unsuccessful:

⚠ Ownership verification failed.

The information provided did not sufficiently match the owner's private evidence.

[Request Additional Verification]

Do NOT expose the correct answers.
